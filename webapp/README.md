# PourPour

Web app: название или фото пачки → этикетка кофе → рецепт воронки.

Распознавание фото и подбор рецепта для нового кофе описаны в [ML README](../ml/README.md).
Фото обрабатывается локально (Tesseract + Pillow), после распознавания удаляется.
Для известного кофе показываем исходный рецепт; для нового — явно отмеченное предложение
на основе похожего лота из датасета. Текст этикетки можно проверить и исправить.

## Запуск

Для поиска в живом каталоге нужен Python 3.11+ и доступ в интернет; внешних библиотек не требуется.
Для фото нужны Tesseract, Pillow и языковые веса: [инструкция установки](../ml/README.md#install-and-run).
API-ключи не нужны. Подбор по сохранённой базе и распознавание фото после установки работают без сети.

```sh
python3 server.py
```

Открыть http://127.0.0.1:8000. Для другого порта: `python3 server.py --port 8080`.

## Возможности

- Поиск по названию, его части и транслитерации; похожие названия при опечатке отмечаются отдельно.
- Только лоты с обжаркой под фильтр из текущей выгрузки. Фасовки одного лота объединяются.
- Только рецепты `DRIPPER`; эспрессо, аэропресс и батч-брю исключаются.
- Доза, вода, температура, общее время, исходная настройка кофемолки, шаги и накопительный вес воды на весах.
- Переключение вариантов рецепта, если источник вернул несколько.
- Таймер с паузой, сбросом и подсветкой текущего вливания. Самостоятельно не управляет кофемашиной.
- Ссылки на карточку кофе и исходные данные, время загрузки и отметка устаревшего кэша.
- Мобильный интерфейс, управление с клавиатуры, отдельные состояния ошибок и отсутствующего рецепта.

## Как получаем рецепт

1. Читаем публичную YML-выгрузку: https://theweldercatherine.ru/bitrix/catalog_export/yandex_848006.php.
2. Выбираем фасовки с `(под фильтр/…)`, объединяем по URL карточки, ищем название локально.
3. В выбранной карточке читаем `#recipe-template[data-id]`. Это ID лота, а не ID фасовки из YML.
4. Читаем публичный API, используемый сайтом: `https://recipes.theweldercatherine.ru/api/v1/recipes?product_id=…&view=true`.
5. Оставляем `device.kind == DRIPPER`, сортируем шаги по `seq_num`. Значения `s`, `1ms`, `2ms` трактуются как 0, 60, 120 секунд, как в скрипте самого источника. Помол отображается в исходном формате `grind_step.grind_sub_step` без самостоятельного пересчёта шкал.

Проверено 15 сентября 2026 на живом каталоге и рецепте «Руанда Суса»: 15 г / 250 г / 98 °C / 2:55, пять вливаний по 50 г.

## API приложения

- `GET /api/search?q=руанда` — результаты, тип совпадения и метаданные источника.
- `GET /api/recipes/{id}` — рецепт выбранного результата поиска.
- `GET /api/health` — состояние локального сервера, без проверки внешнего источника.

`id` выдаёт наш поиск; произвольные внешние URL API не принимает. Ошибка источника — HTTP 502, неизвестный лот — 404, неверный ввод — 400. Нет рецепта воронки — успешный ответ с пустым `recipes`.

## Кэш и ограничения

Каталог кэшируется на 6 часов, ID карточки — на сутки, рецепты — на час. Кэш хранится в `.cache/` и исключён из Git. При недоступности источника сохранённые данные не старше 7 дней показываются с предупреждением и прежней датой загрузки. Запросы к источнику последовательные, с интервалом минимум 350 мс, тайм-аутом 15 секунд и ограничением ответа 8 МБ. Редиректы запрещены, хосты ограничены двумя доменами источника.

Архив не индексируется. Для некоторых лотов рецепт отсутствует или заполнен частично; приложение показывает это явно. Общий рецепт не подставляется. В режиме фото/текста модель может предложить исходный рецепт похожего кофе из сохранённой базы; это не проверенная персонализация вкуса.

Сервер стандартной библиотеки предназначен для локального MVP. Публичное развёртывание требует production-сервера/reverse proxy, HTTPS, ограничения частоты запросов и мониторинга источника. Не публиковать этот сервер напрямую в интернет как готовый production-сервис.

## Проверки

```sh
python3 -m unittest discover -s tests -v
```

Тесты работают без сети. Фикстуры — минимальные фрагменты структуры публичных ответов, полученных 15 сентября 2026. Проверяются разделение способов приготовления, порядок шагов, формат времени, неполные данные, поиск, объединение фасовок, ошибки и устаревание кэша.
